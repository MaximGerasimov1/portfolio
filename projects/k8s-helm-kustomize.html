Шаблонизация развёртывания: Kustomize и Helm

Одна и та же конфигурация собирается двумя способами, чтобы новое окружение не означало копию всех манифестов.

Задача

К этому моменту приложение описывали простые манифесты: девять деплойментов, сервисы, ConfigMap, Secret, PV/PVC, Ingress и сертификат. Каждое новое окружение означало бы копию всего набора файлов с правкой нескольких значений — дублирование, которое быстро расходится. Нужно было вынести общее в одно место, а различия оставить точечными.

Что сделано

Kustomize: база и оверлей.

  • Разложил конфигурацию на base (неймспейс, деплойменты, сервисы, PV/PVC, Ingress, Issuer, Certificate) и оверлей production.
  • ConfigMap и Secret оверлей генерирует сам: configMapGenerator из configmap.env и init.sql, secretGenerator — из secrets.env и файлов ключей.
  • Включил disableNameSuffixHash: true: по умолчанию Kustomize добавляет к именам хэш содержимого, а деплойменты ссылаются на ConfigMap и Secret по фиксированным именам — без этого флага поды не находят конфигурацию.
  • Отличие production от базы описано одним replicas-patch.yaml, поднимающим gateway-service до трёх реплик; всё остальное наследуется.

Helm: тот же набор через шаблоны.

  • Деплойменты и сервисы семи приложений генерируются одним шаблоном в цикле по .Values.services — образ, порт, число реплик и ключ базы данных стали параметрами записи, а не семью почти одинаковыми файлами.
  • Postgres, RabbitMQ, ConfigMap, Secret, PV/PVC, Ingress, Issuer и Certificate описаны отдельными шаблонами; общие имена и метки вынесены в _helpers.tpl, инициализирующий SQL подставляется через .Files.Get.
  • Чарт упакован через helm package, установлен через helm install, изменение в values.yaml выкачено через helm upgrade.

Фрагмент

# overlays/production/kustomization.yaml

resources:
  - ../../base
namespace: basic-kuber
configMapGenerator:
  - name: environments
    envs: [files/configmap.env]
generatorOptions:
  disableNameSuffixHash: true
patches:
  - path: replicas-patch.yaml

# helm — сервисы генерируются циклом по values

{{- range $name, $svc := .Values.services }}
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ $name }}-svc
spec:
  replicas: {{ $svc.replicas }}
  ...
{{- end }}

Результат

  • Конфигурация не дублируется: новое окружение — dev, stage, test — добавляется оверлеем поверх той же базы или своим файлом values, без копирования девяти манифестов.
  • Добавление сервиса в Helm-варианте — это запись в values.yaml, а не ещё одна пара манифестов deployment + service.
  • Одно приложение описано двумя инструментами — видна разница подходов: Kustomize накладывает патчи на готовый YAML, Helm генерирует YAML из шаблонов и параметров.
