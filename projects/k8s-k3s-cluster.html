Собственный кластер k3s: Ingress, TLS и постоянное хранилище

Переход с одноузлового minikube на самостоятельно собранный кластер из трёх узлов с единой точкой входа по HTTPS.

Задача

В предыдущем проекте приложение жило в minikube: доступ к сервисам шёл через туннели minikube service, а данные Postgres пропадали вместе с подом. Нужно было собрать многоузловой кластер, дать приложению одну точку входа по доменному имени с TLS и сделать так, чтобы база переживала пересоздание пода.

Что сделано

  • Собрал кластер k3s из трёх узлов. Vagrantfile поднимает ВМ в приватной сети и запускает provision-скрипты: на мастере k3s server со снятым штатным Traefik (--disable=traefik), на воркерах k3s agent с подключением по K3S_URL и общему токену. Скрипт мастера сразу раскладывает kubeconfig в домашний каталог пользователя, чтобы kubectl работал без sudo.
  • Поставил ingress-nginx вместо Traefik — официальным манифестом контроллера — и сделал его единой точкой входа на портах 80 и 443.
  • Настроил выпуск сертификатов. Установил cert-manager, описал ClusterIssuer (self-signed) и объект Certificate на wildcard-имя со сроком действия 90 дней и обновлением за 10 дней до конца. cert-manager сам следит за секретом и перевыпускает пару ключей — обновлять сертификат руками не нужно.
  • Описал Ingress для двух публичных путей приложения (авторизация и gateway), привязав его к ingress-nginx и выпущенному сертификату. Внутренние сервисы наружу не выставлены.
  • Вынес данные Postgres на узел. Описал PersistentVolume (hostPath, 5 Gi) и PersistentVolumeClaim; каталог под данные создаётся provision-скриптом воркера.
  • Развернул Prometheus Operator в отдельном неймспейсе для сбора метрик кластера.

Фрагмент

# k3s-master.sh — сервер без штатного Traefik

curl -sfL https://get.k3s.io | \
  INSTALL_K3S_EXEC="server \
    --disable=traefik \
    --node-ip=192.168.33.10 \
    --token=$K3S_TOKEN" sh -

# certificate.yaml — автообновление

spec:
  secretName: my-tls-keys
  duration: 2160h     # 90 дней
  renewBefore: 240h   # за 10 дней до конца
  issuerRef:
    name: selfsigned-issuer
    kind: ClusterIssuer

Результат

  • Приложение доступно снаружи по одному доменному имени поверх HTTPS — вместо набора туннелей к каждому сервису.
  • Сертификат перевыпускается автоматически, ручных операций с ключами нет.
  • Данные Postgres не теряются при пересоздании пода.
  • Конфигурация кластера воспроизводима: vagrant up собирает те же три узла с теми же версиями компонентов.
