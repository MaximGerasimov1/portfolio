Project 08: Infrastructure Automation & Service Discovery

Project Overview

Проект сфокусированный на Infrastructure as Code (IaC). Задача заключалась в полной автоматизации настройки парка виртуальных машин с помощью Ansible и реализации динамического обнаружения сервисов (Service Discovery) через Consul.

Key Accomplishments

  • Ansible Roles Development: Создана модульная структура ролей для установки Consul (Server/Client), базы данных PostgreSQL и Java-микросервиса.
  • Service Discovery & Mesh: Настроен Consul Connect для обеспечения безопасной сетевой связности между API и DB без использования жестко прописанных IP-адресов.
  • Automated Provisioning: Развернут кластер из 3-х нод (Manager, API, DB) через Vagrant, где вся настройка софта происходит «одной кнопкой» через Ansible Playbook.
  • Deep Troubleshooting: Проведен дебаг микросервиса, в ходе которого выявлена ошибка типизации данных (Long vs Integer) в Spring-контроллере при работе с PostgreSQL.
  • Remote Configuration: Реализовано управление конфигурациями через Jinja2 шаблоны для генерации файлов consul.hcl.

Automation Workflow

Ниже представлены фрагменты основного плейбука и конфигурации Consul Connect, которые связывают сервисы в единую экосистему.

# site.yml (Main Playbook)
- hosts: consul_server
  roles:
    - install_consul_server

- hosts: api, db
  roles:
    - install_consul_client

- hosts: db
  roles:
    - install_db
# consul_client.hcl (Connect)
connect {
  sidecar_service {
    proxy {
      upstreams {
        destination_name = "db"
        local_bind_port = 5432
      }
    }
  }
}
# Ansible Task (Service Install)
- name: Start the hotels-service
  systemd:
    name: hotels
    state: started
    enabled: yes
    daemon_reload: yes
# Verification (Consul UI)
# Проверка регистрации сервисов
consul catalog services
# Доступ через проброшенный порт
http://localhost:8500/ui
