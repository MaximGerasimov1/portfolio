network

Сетевой стенд: маршрутизация, файрвол, NAT

Переход от одного сервера к сети из нескольких машин и двух маршрутизаторов с изолированными подсетями.

Задача

Спроектировать и собрать сетевой стенд, обеспечить связность между изолированными подсетями и — главное — научиться определять, на каком именно узле теряется трафик, вместо перебора настроек наугад.

Что сделано

  • Расчёт адресации. Разбиение на подсети и расчёт масок через ipcalc; схема стенда спроектирована до его сборки.
  • Статическая маршрутизация. Настроил адреса узлов, включил IP-форвардинг на маршрутизаторах, задал маршрут по умолчанию и статические маршруты между подсетями — сначала вручную, затем с сохранением в конфигурации, чтобы они переживали перезагрузку.
  • Динамическая адресация. Поднял isc-dhcp-server и проверил получение адресов клиентами после перезагрузки.
  • NAT. Настроил трансляцию адресов, чтобы машины внутренней сети получили доступ во внешнюю.
  • Файрвол. Правила iptables для ограничения трафика между сегментами сети.
  • Диагностика. ping и traceroute для построения пути пакета, разбор поведения ICMP при недоступном маршруте, замер пропускной способности каналов через iperf3.
  • SSH-туннели. Local TCP forwarding для доступа к веб-серверу на машине, недоступной напрямую.

Результат

  • Связность между всеми подсетями подтверждена тестами, а не предположениями.
  • При отказе связности видно, на каком узле теряется пакет: таблица маршрутизации, правила файрвола и вывод traceroute дают ответ за минуты.
  • Появился навык, который дальше применялся в каждом проекте с несколькими виртуальными машинами — от Docker Swarm до кластера k3s.
