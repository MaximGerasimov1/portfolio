orchestration

Оркестрация микросервисов в Docker Swarm

Начало сквозной линии: одно микросервисное приложение — 7 сервисов на Spring Boot, PostgreSQL и RabbitMQ — которое дальше проходит через проекты 08–13.

Задача

Приложение из семи сервисов не помещается на одну машину и не управляется командами docker run: нужны распределение контейнеров по узлам, сеть между ними и единая точка входа, закрывающая внутренние API от прямого доступа.

Что сделано

  • Контейнеризация сервисов. Написал Dockerfile для Java-сервисов на базе openjdk-alpine. Отдельно решил проблему сборки: зависимости Maven подтягиваются слоем mvn dependency:go-offline до копирования исходников, чтобы пересборка не тянула их заново.
  • Стенд как код. Vagrantfile разворачивает три узла (1 manager, 2 worker) и устанавливает на них Docker shell-скриптами — кластер собирается с нуля одной командой.
  • Кластер Swarm. Инициализировал кластер, подключил воркеров, развернул приложение через docker stack deploy, настроил распределение сервисов по узлам.
  • Сеть и изоляция. Создал оверлейную сеть для взаимодействия сервисов между узлами и поставил Nginx входной точкой: наружу открыты только публичные маршруты, gateway и session напрямую недоступны.
  • Наблюдение за кластером. Развернул Portainer для просмотра состояния узлов, сервисов и контейнеров.

Результат

  • Приложение разворачивается в кластере одной командой и переживает падение отдельного контейнера — Swarm перезапускает задачу сам.
  • Топология воспроизводима: vagrant up собирает те же три узла с той же конфигурацией, независимо от состояния рабочей машины.
  • Внутренние сервисы недоступны снаружи напрямую — трафик идёт только через Nginx.
