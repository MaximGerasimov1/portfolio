Project 07: Container Orchestration (Docker Swarm)

Project Overview

Проект посвящен переходу от одиночных контейнеров к полноценной оркестрации микросервисного приложения. Основной задачей стала настройка кластера Docker Swarm на виртуальных машинах, поднятых через Vagrant, и обеспечение связи между сервисами через изолированные оверлейные сети.

Key Accomplishments

  • Microservices Dockerization: Созданы оптимизированные Dockerfile для Java-сервисов (openjdk-alpine). Решена проблема с зависимостями Maven путем интеграции установки mvn непосредственно в образ.
  • Infrastructure as Code: Написан Vagrantfile для автоматического развертывания трех узлов (1 Manager, 2 Workers) с автоматической установкой Docker через shell-скрипты.
  • Swarm Cluster Setup: Инициализирован кластер и настроено распределение контейнеров по узлам. Реализован механизм stack deploy.
  • Network Security: Настроена оверлейная сеть и Nginx-прокси, ограничивающий прямой доступ к внутренним API (gateway и session services).
  • Visual Monitoring: В кластер внедрен Portainer для визуального контроля состояния нод, сервисов и контейнеров в реальном времени.

Configuration & Troubleshooting

Примеры исправленного Dockerfile и конфигурации оркестрации кластера.

# Dockerfile (Fixing Maven issues)
FROM openjdk:8-jdk-alpine
RUN apk add --no-cache maven bash
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline -B
COPY src/ src/
RUN mvn package -DskipTests
# Vagrantfile (Multi-node setup)
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/bionic64"
  config.vm.define "manager01" do |m|
    m.vm.network "private_network", ip: "192.168.33.10"
    m.vm.provision "shell", path: "install_docker.sh"
  end
end
# docker-compose.yml (Fragment)
session-service:
    build: "./services/session-service"
    image: gisellet/session-service:latest
    networks:
        - hotel-overlay-net
    depends_on:
        - db
# Proxy Logic (Nginx)
location /api/session {
    proxy_pass http://session_service:8081;
    proxy_set_header Host $host;
}
