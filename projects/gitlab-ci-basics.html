ci/cd

Первый CI/CD-пайплайн на GitLab CI

Первая автоматизация поставки: от коммита до приложения на сервере без ручных шагов.

Задача

Сборка, проверка стиля, тесты и выкладка выполнялись вручную и в произвольном порядке — ошибку легко было выкатить незамеченной. Нужно было связать шаги в конвейер, который выполняется на каждый коммит и останавливается на первой же неудаче.

Что сделано

  • Развернул GitLab Runner на отдельной машине и зарегистрировал его в проекте.
  • Стадия build — сборка проекта через Makefile.
  • Стадия code style — статическая проверка clang-format; несоответствие стилю останавливает конвейер до запуска тестов.
  • Стадия test — модульные тесты; падение теста блокирует выкладку.
  • Стадия deploy — доставка собранного артефакта на целевой сервер по SSH и его запуск.
  • Уведомления. Написал Bash-скрипт, который по завершении пайплайна отправляет статус каждой стадии в Telegram через Bot API.

Результат

  • Ошибка сборки, нарушение стиля или упавший тест обнаруживаются автоматически и не доходят до сервера.
  • Выкладка перестала быть ручной операцией: после успешного прохождения стадий приложение оказывается на сервере само, а статус приходит в мессенджер.
  • Этот пайплайн — прототип конвейера, который позже собирается уже внутри Kubernetes-кластера.
