Сборка нативной библиотеки: CMake, Docker, CI и провижининг

Тестовое задание: один исходный код собирается вручную под Linux и Windows, в контейнере, на подготовленной Ansible виртуальной машине и в CI-конвейере.

Задача

Собрать SQLite в виде динамической библиотеки — .so под Linux и .dll под Windows — и довести процесс до состояния, когда сборка не зависит от того, на какой машине она запускается: описать её кодом, изолировать окружение и вынести в конвейер.

Решение

Что сделал

  • Кроссплатформенная сборка. Один CMakeLists.txt собирает разделяемую библиотеку и линкует с ней консольную утилиту. Различия компиляторов вынесены в условия: под Windows экспорт символов включается через __declspec(dllexport), под Linux подключаются pthread, dl и m.
  • Изолированное окружение. Multi-stage Dockerfile: первый слой ставит тулчейн и собирает проект, второй — чистый debian:stable-slim, куда копируются только артефакты. В финальном образе нет ни компилятора, ни исходников.
  • Отладка сборки образа. docker build падал на mkdir: cannot create directory 'build' — в контекст сборки попадал локальный каталог build/ от ручной сборки. Добавил .dockerignore, и контекст перестал зависеть от состояния рабочей машины.
  • Провижининг стенда. Vagrantfile поднимает ВМ на Debian и запускает Ansible-плейбук: тулчейн, Docker (репозиторий и GPG-ключ по официальной инструкции, а не curl | sh), загрузка исходников, сборка библиотеки, сборка образа и проверка запуском контейнера — одной командой.
  • CI-конвейер. Две стадии: build_lib собирает библиотеку и отдаёт её вместе с логами конфигурации и компиляции в артефакты; build_image собирает образ в docker:dind и публикует его в registry. Учётные данные берутся из переменных CI.
  • Управление зависимостями. Отдельный пример с Conan: пакетный менеджер подтягивает zlib, генерирует toolchain-файл для CMake, приложение линкуется без установки зависимости в систему.

Результат

  • Одно описание сборки покрывает Linux, Windows и контейнер.
  • Финальный образ содержит только библиотеку и утилиту — компилятор и исходники остаются в промежуточном слое.
  • Сборка не зависит от состояния рабочей машины: контекст Docker очищен, окружение разворачивается плейбуком, исходники скачиваются по фиксированной версии.
  • Конвейер собирает библиотеку, сохраняет логи компиляции как артефакты и публикует образ в registry без ручных шагов.
